<summary><strong>Instructor Answer Key</strong> (review after this module — collapsed for in-class use)</summary>

**1.** A — the first-encounter sequence from Topic 1: find the entry point (`server.js`, `main`), state the purpose in a paragraph, identify the major components, *then* go deep. B is how people drown — nobody reads a real codebase end to end, and the bug is in one place. C is the instinct that gets new developers in trouble: you don't yet know *why* the code is the way it is, and "I'd have written it differently" is not a bug report. D isn't wrong to *use* — an assistant is genuinely good at explaining a function you're already looking at — but it's wrong as a substitute for reading, which is the same **🤖 verify-the-output** point as Question 2.

**2.** *Good uses:* explaining unfamiliar code, scaffolding/boilerplate, suggesting fixes, drafting tests, looking things up faster. *Why review:* it can be confidently wrong, produce subtle bugs or insecure/outdated code, miss your context, or "hallucinate" APIs — you stay responsible for what ships. Any one of each is enough. (This is the course's recurring **🤖 verify-the-output** discipline.)

**3.** *Listen for:* a genuine link between a concrete interest and one of the three directions, plus a thread back to this week (e.g., "the API demo interested me → back-end and data work → that's the CivicTrack endpoint we called in Demo 26"). Reward self-awareness over a "correct" choice.

**Muddiest Point / Connect It:** Not graded. These are the most valuable signals of the week — the Muddiest Points tell you what to reinforce before the class walks out the door, and the Connect-it reflections gauge whether the CivicTrack thread tied the week together and whether learners have a real next step. Consider sharing common themes (anonymized) as a closing recap.
