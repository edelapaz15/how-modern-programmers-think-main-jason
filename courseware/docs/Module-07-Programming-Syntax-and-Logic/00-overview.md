# Module VII: Programming Syntax & Logic

*From Concepts to Real Code*

## Module Overview

You've spent the previous modules building mental models. You've learned how programmers think about problems, how to work with data, how databases store information, and how algorithms solve computational problems—all through pseudocode, flowcharts, and conceptual frameworks.

Now it's time to stop thinking about programming and start doing it.

This module marks a critical transition point in your journey. You'll move from understanding *what* programmers do to understanding *how* they actually do it, using real programming languages, real syntax, and real execution environments. The ideas you've learned haven't changed—we're just expressing them in the languages computers actually understand.

> **🔗 Course Project Thread: CivicTrack**
> This is where you write a small piece of [CivicTrack](../../course-project/README.md)'s real logic in JavaScript—turning the "submit a request" steps you decomposed earlier into code that actually runs. The version you write here is your first real line of CivicTrack.

## Learning Objectives

By the end of this module, you will be able to:

1. **Understand syntax and semantics** — the difference between grammar (syntax) and meaning (semantics) in programming languages
2. **Compare language categories** — explain the differences between compiled, interpreted, and JIT-compiled languages
3. **Write JavaScript code** — use variables, functions, control flow, and data structures to solve problems
4. **Use a professional development environment** — set up VS Code, run code, debug, and read error messages
5. **Understand the web stack** — see how JavaScript, HTML, CSS, databases, and servers fit together
6. **Transition to a compiled language** — learn Java syntax and understand key differences from JavaScript
7. **Read real error messages** — interpret compiler errors, runtime exceptions, and logic errors
8. **Choose appropriate tools** — match language selection to problem requirements and team context

## How to Use This Module

This module is designed for adult learners transitioning into programming:

- **Read the overview sections first** to understand the "why" before diving into code
- **Type out the code examples yourself** rather than copy-pasting. Your hands learning the syntax is part of the process
- **Experiment** — modify the examples, break them, fix them, make them do new things
- **Connect to what you already know** — use the business parallels sections to anchor new concepts in familiar territory
- **Work through the discussion questions** — they prepare you to explain these concepts to others or your future self

You don't need to rush through—take time with code examples, experiment, and let ideas settle before moving forward.

## Prerequisites

You should have:
- Completed Modules I–VI (understanding algorithmic thinking, data structures, databases, etc.)
- A computer with internet access
- VS Code installed and configured (from Module III)
- Patience and curiosity—programming is learnable, but not all at once

### What This Module Is NOT

- **Not a complete JavaScript reference** — we cover fundamentals, not every built-in function
- **Not a complete Java reference** — Java has vast libraries; we focus on core language features
- **Not a deep dive into web development frameworks** — React, Angular, and Vue are beyond this module
- **Not advanced object-oriented programming** — inheritance, polymorphism, and design patterns come later

Instead, this module is a **bridge** from concepts to code, giving you the foundation to learn more advanced topics independently.

## Key Themes Throughout This Module

Throughout this module, you'll notice several repeating themes:

### **Business and Programming Parallels**
Just as your business uses multiple tools for different jobs, programmers use multiple languages. A company might use Excel spreadsheets, SQL databases, and specialized software—just as programmers use JavaScript, Java, Python, and Go for different problems. Understanding why requires understanding the tools themselves.

### **From Pseudocode to Real Code**
The pseudocode you wrote earlier is nearly valid in many real languages. You'll see how natural-language-like logic becomes real, executable code.

### **Debugging is Reading**
The most valuable skill this module develops isn't writing perfect code—it's reading error messages, understanding what went wrong, and fixing it. This applies whether you work in programming or any technical field.

### **Language Matters, But Ideas Matter More**
Different languages have different syntax, but the core concepts—variables, functions, loops, conditionals—appear everywhere. Learn these concepts once, and picking up a third or fourth language becomes much easier.
